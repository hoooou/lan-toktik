# 推荐 Tab 设计文档（内容标签推荐）

日期：2026-08-10
状态：已与用户逐段确认

## 1. 目标与形态

- 新增第 4 个「推荐」Tab：全屏滑动流，交互与现有 Tab 一致（点赞/收藏/删除按钮不变）
- 每条视频信息区显示**推荐理由**（如"因为你看过「乱伦」类"、"因为你偏好短片"、"热门视频"）
- 单人画像（`default`），数据结构预留 `profiles` 多画像扩展位（本期不做多画像）

## 2. 学习信号

### 显式信号
点赞 / 取消点赞 / 收藏 / 取消收藏 / 删除

### 隐式信号
观看时长（5 秒节流上报）、完成（播放到结尾）、快速划走（进视频 <10 秒）、长按 2x 加速、向前跳转（点击快进 / 进度条向前拖 / →键）、后退回看（←键）

### 快进类边界规则
- 快进到 >90% 位置 → 视为 `finish` 完成，不再记负向（跳过无聊部分但看完核心，不否定）
- 一次长按 2x 只记一次 `speedup`（按住多久都算一次）
- 一次进度条拖拽记一次 `seek_fwd` / `seek_back`

## 3. 架构与数据流

```
浏览器客户端 (index.html)                 server.js（零依赖，仅 Node 内置模块）
  │  POST /api/events（批量上报）             │
  ├────────────────────────────────────────▶ │ 推荐模块（新增）
  │  GET /api/recommend（排序+理由）          │     │
  │ ◀────────────────────────────────────────┤     ▼
  │  静态 /data/covers/*.jpg（封面缩略图）     │  data/recommend.json（画像，fs 读写）
  │                                          │  data/media-meta.json（元数据缓存）
  └──────────────────────────────────────────┘  data/covers/（封面图）
```

### 新增接口
- `POST /api/events` — 批量上报行为事件，服务端原子更新画像
- `GET /api/recommend` — 返回 `[{ name, reason, groupId }]`（按兴趣排序 + 推荐理由 + 副本组标识）
- 静态 `/data/covers/<name>.jpg` — 封面缩略图

### 新增数据文件
- `data/recommend.json`：`{ profiles: { default: { tagWeights, videoStats, seen } } }`（`profiles` 为多画像预留，当前仅 `default`）
- `data/media-meta.json`：`{ "<文件名>": { duration, width, height, cover } }`
- `data/covers/`：封面图目录

## 4. 标签系统与兴趣向量（算法核心）

### 词表
- 服务端内置约 40-60 个高频中文题材词（从现有 513 个文件名提取）：乱伦、海角、姐姐、妹妹、嫂子、淫妻、表妹、白丝、黑丝、巨乳、白虎、口爆、内射、深喉、骑乘、后入、自慰、直播、调教、少女……
- 硬编码数组（零依赖哲学，不引 NLP 库）
- 匹配规则：文件名包含词即打标签（一视频可多标签）；不含任何词 → 无标签，靠行为分兜底

### 元数据标签（ffprobe，硬性依赖）
- 时长：短(<60s) / 中(1-5min) / 长(>5min)
- 分辨率：标清(<720p) / 高清(720p) / 超清(1080p) / 4K(≥2160p)
- **清晰度独立维度**：快速划走低清片只降清晰度权重，不伤内容标签

### 权重更新规则
| 行为 | 标签权重变化 |
|---|---|
| 点赞 / 收藏 | +3 |
| 看完（≥90%） | +2 |
| 观看 ≥30% 未划走 | +0.5 |
| 快速划走（<10s） | -1 |
| 删除 | -3 |
| 长按 2x（speedup） | -0.5 |
| 点击快进 / 前拖 / ←（seek_fwd） | -1 |
| 后退回看 / →（seek_back） | +1 |

### 排序公式
`score = Σ(该视频标签的权重) + 行为分`

行为分 = 播放次数×0.3 + 完成率×1.5 + 最近看过 -1（防止反复推荐刚看完的）

无标签视频只有行为分，可被热门行为分顶上。

### 推荐理由（排序后取）
- 标签得分最高 → "因为你看过「乱伦」类"
- 无标签但行为分高 → "你看过多次" / "热门视频"
- 新片 → "新片推荐"

## 5. 副本分组

文件名去掉 `_ 51吃瓜网`、`-20260808-xxx` 等来源/日期后缀后相同 → 同一组。
推荐流一组只出一条；其余同组视频标注"同类还有 X 个版本"。

## 6. 媒体元数据扫描（scan-metadata.js）

- 独立脚本，服务端启动时后台跑一次 + 手动可跑
- 用 `ffprobe` 读时长、分辨率 → 派生时长/清晰度标签
- 用 `ffmpeg` 抽帧（视频 10% 位置，约 320px 宽 JPG）存 `data/covers/<name>.jpg`
- 增量更新：对比 media 目录与 `data/media-meta.json`，只处理新增/变更文件
- **ffmpeg/ffprobe 为硬性依赖**：启动时检测，缺失则报错退出，不做静默降级

## 7. 客户端埋点与改动

### 事件表
| 事件 | 触发 | 上报内容 |
|---|---|---|
| watch | 播放中每 5 秒节流 / 暂停 / 切走 | 视频名、已看秒数 |
| finish | 播放到结尾 | 视频名 |
| skip | 进视频 <10 秒划走 | 视频名 |
| like / unlike | 点爱心 | 视频名 |
| fav / unfav | 点收藏 | 视频名 |
| delete | 点删除 | 视频名 |
| speedup | 长按 2x | 视频名 |
| seek_fwd | 向前跳转：点击快进 / 进度条前拖 / →键 | 视频名 |
| seek_back | 后退回看：←键 | 视频名 |

- 批量上报：离开页面 / 切换 Tab / 30 秒定时，攒一批发一次 `POST /api/events`
- `like/fav` 仍存 localStorage（UI 状态），同时复制一份到服务端画像（学习真源）

### 推荐 Tab
- 第 4 个 Tab 按钮（推荐/全部/收藏/已删除），进 Tab 拉 `GET /api/recommend` 渲染滑动流
- 推荐理由显示在视频信息区
- 封面缩略图：理由旁小图（`/data/covers/xxx.jpg`），加载失败静默（仅 UI 容错）

### 排除与联动
- 推荐流不含回收站文件（服务端读 `.trash` 目录过滤）
- 删除 → 推荐流消失；还原 → 重新出现

## 8. 测试

- 服务端单元自测（node 内置 test）：词表匹配、权重更新、排序、副本分组、排除逻辑
- ffprobe 扫描：跑真实 513 文件（预计几十秒），抽查时长/分辨率正确性
- 客户端手工：推荐 Tab 加载、理由显示、点赞后刷新顺序变化、快速划走几次后同类权重下降
- 全流程：删除 → 推荐流消失 → 还原 → 重现
